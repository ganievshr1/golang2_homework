# Gateway и Ledger на Go

Учебный проект из двух независимых сервисов:

- Gateway — HTTP-сервис с маршрутом GET /ping.
- Ledger — хранение транзакций и контроль бюджетов по категориям.

У каждого сервиса собственный go.mod.
Используется только стандартная библиотека Go.

## Требования

- Go 1.22 или выше.
- Git.
- Для отправки изменений — доступ к репозиторию GitHub.

Проверка установки:

```bash
go version
git --version
```

## Структура проекта

| Файл | Назначение |
| --- | --- |
| gateway/go.mod | Модуль Gateway |
| gateway/main.go | HTTP-сервер на порту 8080 |
| gateway/main_test.go | Проверки HTTP-ответов |
| ledger/go.mod | Модуль Ledger |
| ledger/main.go | Запуск и демонстрация операций |
| ledger/transactions.go | Хранение транзакций и проверка бюджета |
| ledger/budgets.go | Budget, SetBudget и LoadBudgets |
| ledger/budgets.json | Начальные бюджеты |
| ledger/transactions_test.go | Проверки транзакций |
| ledger/budgets_test.go | Проверки бюджетов, JSON и сценария main |
| .gitignore | Исключения для Git |
| README.md | Инструкция |

Внешних зависимостей нет, поэтому go.sum не требуется.

Общего go.mod в корне нет:
команды Go выполняются отдельно внутри gateway и ledger.

## Запуск Gateway

Откройте терминал в корне finance-services:

```bash
cd gateway
go run .
```

Сервис работает на порту 8080 до нажатия Ctrl+C.

В другом терминале выполните:

```bash
curl -i http://localhost:8080/ping
```

Для Windows PowerShell:

```powershell
curl.exe -i http://localhost:8080/ping
```

Ожидаемый результат:

- HTTP-статус: 200 OK.
- Тело ответа: pong.

Другие методы на /ping возвращают 405.
Неизвестный путь возвращает 404.

## Запуск Ledger

Откройте новый терминал в корне finance-services:

```bash
cd ledger
go run .
```

Текущей директорией должна быть ledger:
именно здесь расположен budgets.json.

Используйте `go run .`, чтобы Go включил все файлы пакета.

Ledger выполняет демонстрацию и завершает работу.
HTTP/gRPC-интерфейс Ledger и взаимодействие с Gateway
на этом этапе не реализованы.

## Формат денежных сумм

Transaction.Amount и Budget.Limit задаются целыми числами в копейках.

Примеры:

- 100 = 1 рубль.
- 150050 = 1500 рублей 50 копеек.
- 500000 = 5000 рублей.

Целочисленный формат исключает погрешности float64.

Положительная транзакция означает расход.
Отрицательная транзакция означает возврат и уменьшает расходы категории.

## Файл бюджетов

Начальные бюджеты находятся в ledger/budgets.json:

```json
[
  {
    "category": "Продукты",
    "limit": 500000
  },
  {
    "category": "Транспорт",
    "limit": 200000
  }
]
```

Категории сравниваются точно, с учётом регистра и пробелов.

Бюджет фиксированный и учитывает всю историю категории
за время работы текущего процесса.

Автоматического сброса бюджета по месяцам нет.
Поле Date не влияет на расчёт лимита.

## Функции Ledger

```go
func SetBudget(b Budget)
func LoadBudgets(r io.Reader) error
func AddTransaction(tx Transaction) error
func ListTransactions() []Transaction
```

### SetBudget

Добавляет или обновляет бюджет в map[string]Budget.

Для прямого вызова из Go передавайте непустую категорию
и неотрицательный лимит.

Изменение бюджета не удаляет историю транзакций.

Если новый лимит ниже уже потраченной суммы,
следующая операция разрешается только при условии,
что итоговая сумма укладывается в новый лимит.

### LoadBudgets

Читает один JSON-массив через json.Decoder.

Проверяет:

- корректность JSON;
- наличие непустой категории;
- наличие неотрицательного целого limit;
- отсутствие неизвестных полей;
- отсутствие лишних данных после массива;
- ошибки чтения.

Бюджеты обновляются через SetBudget только после проверки всего массива.

При ошибке существующие бюджеты остаются без изменений.

Пустой массив [] ничего не меняет.
При повторении категории используется её последнее значение.
Неупомянутые категории сохраняются.

В main файл открывается через os.Open,
а чтение выполняется через bufio.NewReader.

### AddTransaction

Отклоняет транзакцию с нулевой суммой.

Если у категории есть бюджет, рассчитывает сумму
всех её транзакций вместе с новой:

- меньше лимита — операция разрешена;
- ровно лимит — операция разрешена;
- больше лимита — возвращается ErrBudgetExceeded.

Если бюджет категории отсутствует, ограничение не применяется.

Отклонённая транзакция не сохраняется и не расходует ID.

ID назначается автоматически при успешном добавлении.
Переданный вручную ID заменяется.

Переполнение int при расчёте вызывает ошибку.

Превышение бюджета можно распознать через:

```go
errors.Is(err, ErrBudgetExceeded)
```

### ListTransactions

Возвращает независимую копию списка.
Изменение полученного среза не изменяет хранилище.

## Демонстрация при запуске

С исходным budgets.json:

1. Загружаются бюджеты:
   «Продукты» — 5000 рублей,
   «Транспорт» — 2000 рублей.
2. Бюджет «Обучение» устанавливается в 300 рублей
   и обновляется до 500 рублей.
3. Покупка продуктов на 1500,50 рубля проходит.
4. Следующая покупка продуктов на 4000 рублей отклоняется.
5. Покупка на оставшиеся 3499,50 рубля проходит.
6. Возврат 50 рублей освобождает бюджет.
7. Новая покупка на 50 рублей проходит.
8. Транзакция категории без бюджета проходит.
9. Транзакция с нулевой суммой отклоняется.

В выводе присутствуют два сообщения об отказе:

```text
Отказ: Покупка сверх бюджета: budget exceeded: ...
Отказ: Недопустимая нулевая сумма: ...
```

Итог:

```text
Сохранено транзакций: 7
```

Отклонённые транзакции отсутствуют в итоговом списке.

Ошибка отдельной транзакции не останавливает демонстрацию.

Отсутствующий или повреждённый файл бюджетов завершает запуск
с понятной ошибкой и ненулевым кодом выхода.


## Проверка и сборка

Из корня finance-services:

```bash
cd ledger
go test -v -cover ./...
go vet ./...
go build -o ../bin/ledger .
cd ../gateway
go test -v -cover ./...
go vet ./...
go build -o ../bin/gateway .
cd ..
```

В Windows при сборке можно использовать имена
ledger.exe и gateway.exe.

Сборки попадают в bin, которая исключена из Git.

Тесты проверяют:

- сохранение транзакций и назначение ID;
- независимость возвращаемого списка;
- отклонение нулевой суммы;
- расходы ниже, ровно на уровне и выше лимита;
- накопленную сумму нескольких операций;
- возвраты;
- категории без бюджета;
- независимость бюджетов разных категорий;
- обновление бюджета без удаления истории;
- отсутствие отклонённых записей в хранилище;
- защиту от переполнения int;
- загрузку корректного JSON;
- ошибки JSON и чтения;
- отсутствие частичных изменений при ошибке загрузки;
- демонстрационный сценарий main;
- HTTP-ответы Gateway.

## Ограничения

Данные хранятся в памяти процесса и исчезают после его завершения.

Функции рассчитаны на последовательные вызовы.
Перед добавлением параллельных обработчиков потребуется
синхронизация хранилищ.
