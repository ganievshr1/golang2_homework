# Gateway и Ledger: домашнее задание на Go

Два независимых сервиса находятся в одном Git-репозитории. У каждого сервиса
собственный `go.mod`. Используется только стандартная библиотека Go.

## Требования и состав проекта

Нужен установленный Go версии 1.22 или выше. Для работы с репозиторием нужен Git.
Проверить установку: `go version` и `git --version`.

| Папка / файл | Назначение |
| --- | --- |
| `gateway/go.mod` | Модуль HTTP-шлюза |
| `gateway/main.go` | HTTP-сервер на порту 8080 и обработчик `/ping` |
| `gateway/main_test.go` | Проверки HTTP-ответов |
| `ledger/go.mod` | Модуль бизнес-логики |
| `ledger/main.go` | Запуск Ledger и демонстрация транзакций |
| `ledger/transactions.go` | Структура, хранилище и функции работы с транзакциями |
| `ledger/transactions_test.go` | Проверки добавления, ID, ошибки и копирования |

Пути модулей `example.com/finance-services/...` — учебные идентификаторы.
Для локального запуска доступ к этому домену не нужен. Внешних зависимостей
нет, поэтому `go.sum` не требуется. Общего `go.mod` в корне нет: команды Go
нужно выполнять отдельно внутри каждой папки. `go.work` также не требуется.

## Задание 1. Запуск сервисов

Распакуйте архив. Следующие команды начинаются из корня `finance-services`.

**Терминал 1 — Gateway:**

```bash
cd gateway
go run .
```

Сервер слушает порт `8080` и работает до нажатия `Ctrl+C`.
Если порт занят, сначала остановите программу, которая его использует.

**Терминал 2 — Ledger, также из корня проекта:**

```bash
cd ledger
go run .
```

Ledger выводит `Ledger service started`, добавляет три транзакции, показывает
ошибку для нулевой суммы и печатает список. Затем процесс завершается — это
ожидаемо для этого этапа задания. gRPC-сервер пока не реализован, взаимодействия
между сервисами пока нет.

**Проверка Gateway, пока терминал 1 продолжает работать:**

```bash
curl -i http://localhost:8080/ping
```

В Windows PowerShell можно использовать `curl.exe -i http://localhost:8080/ping`,
чтобы вызвать именно curl. Либо откройте `http://localhost:8080/ping` в браузере.

Ожидаются статус `HTTP/1.1 200 OK` и тело `pong` без завершающего перевода строки.
Другие методы на `/ping` возвращают `405 Method Not Allowed` с заголовком
`Allow: GET`, неизвестный путь возвращает `404 Not Found`.

## Задание 2. Транзакции в Ledger

```go
type Transaction struct {
    ID          int
    Amount      int
    Category    string
    Description string
    Date        string
}
```

- `ID` назначается при успешном добавлении: `len(transactions) + 1`.
  Переданный вручную ID заменяется. Удаления транзакций в этой версии нет.
- `Amount` хранится в копейках: `150050` означает 1500 рублей 50 копеек.
  Целые числа позволяют избежать погрешностей `float64` для денежных сумм.
  В этой демонстрации положительная сумма означает расход, отрицательная — возврат.
- `Category` и `Description` — произвольные строки.
- `Date` — строка вида `YYYY-MM-DD`; дополнительной проверки даты пока нет.
- `transactions` — пустой срез `[]Transaction`, инициализируемый при запуске.

Функции находятся в пакете `main` сервиса Ledger:

```go
func AddTransaction(tx Transaction) error
func ListTransactions() []Transaction
```

`AddTransaction` отклоняет сумму `0`, возвращая `error`. Хранилище и следующий
ID при этом не изменяются. При успехе функция сохраняет транзакцию и возвращает
`nil`. Она принимает структуру по значению, поэтому ID исходной переменной
вызывающего кода не изменяется; назначенные ID доступны через `ListTransactions`.

`ListTransactions` возвращает отдельный срез. Поскольку все поля структуры —
числа и строки, копирования элементов достаточно для независимого результата.

Пример вывода `go run .` в папке `ledger`:

```text
Ledger service started
Ожидаемая ошибка: сумма транзакции не должна быть равна 0

Сохранено транзакций: 3
ID: 1 | Сумма: 150050 коп. | Категория: Продукты | Описание: Покупка в магазине | Дата: 2026-09-21
ID: 2 | Сумма: 6500 коп. | Категория: Транспорт | Описание: Проезд в метро | Дата: 2026-09-22
ID: 3 | Сумма: 39900 коп. | Категория: Обучение | Описание: Покупка книги | Дата: 2026-09-23
```

Данные хранятся только в памяти процесса и исчезают после его завершения.
При следующем запуске демонстрационные записи создаются заново. Эта версия
предполагает последовательные вызовы; перед добавлением параллельной обработки
gRPC-запросов хранилищу потребуется синхронизация.

## Проверки

В среде подготовки архива компилятор Go отсутствовал, а загрузить его не удалось.
Поэтому сборка, запуск сервисов, HTTP-запрос к работающему Gateway и выполнение
тестов здесь не подтверждены. Ниже приведены команды для проверки на вашем компьютере.

Из корня проекта:

```bash
cd gateway
go test ./...
go vet ./...
cd ../ledger
go test ./...
go vet ./...
cd ..
```

Тесты проверяют HTTP-статусы и ответы; сохранение полей и последовательные ID;
отклонение нулевой суммы без изменения хранилища; независимость возвращаемого списка.

Запускайте `go run .`, а не `go run main.go`: у Ledger код расположен в двух
исходных файлах, которые должны компилироваться вместе.

## Git и отправка в удалённый репозиторий

Архив содержит локальный Git-репозиторий с коммитом решения. После распаковки
из корня проекта можно посмотреть его состояние:

```bash
git status
git log --oneline -1
```

Удалённый репозиторий не подключён: его адрес не был предоставлен.
Создайте пустой репозиторий на своём Git-сервере. Подставьте его настоящий адрес
вместо `YOUR_REPOSITORY_URL` и выполните:

```bash
git remote add origin YOUR_REPOSITORY_URL
git push -u origin main
```

Для дальнейших изменений после редактирования файлов:

```bash
git add gateway ledger README.md .gitignore
git commit -m "Update Gateway and Ledger"
git push
```

Если в вашем удалённом репозитории уже есть история, сначала клонируйте его,
перенесите туда папки `gateway`, `ledger`, файлы `README.md` и `.gitignore`
из решения без вложенного `.git`, затем сделайте коммит и обычный push.
